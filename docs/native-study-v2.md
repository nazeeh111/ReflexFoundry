# Planned native comparison, version 2

**Preparation only. No native Codex coding process has started in this study.**
Execution requires direct scoped human authority and the ordinary automatic
approval review. Execution also requires confirmation that the current CLI
uses subscription access with no separately billed API provider. Unknown billing
routes must not be used. A run flag does not provide that authority. The earlier
four-process study remains unchanged and will not be resumed by this protocol.

## Question and workload

Does a compiled context decision change independently verified public repair
success, full-workflow wall time, or reported agent token use? This is a small,
controlled comparison, not a claim of causal superiority or production safety.
The supplied trained policy failed promotion and remains withheld.

The two tasks repair Funcy's `first(seq)` and cachetools' `Cache.__getitem__` in
fresh copies of pinned public source. The sequence task checks first-item
consumption and empty/falsey values; the cache task checks stored values,
missing-key behavior, subclass hooks and unchanged size. Only one source file
may change. Official focused and full suites stay mandatory in every arm.
Separate grader source lives outside each candidate checkout. These are supplied
mutations, not naturally occurring issue reports or broad task samples.

The context head trained only on Toolz. Funcy was an earlier external calibration
repository and cachetools an earlier retrieval-test repository. These are new
agent-repair observations, not new independent retrieval holdouts. Pretraining
contamination is not established or ruled out.

## Five arms and resource bound

| Arm | Initial retrieval action |
| --- | --- |
| Original agent | Normal native context tools on a bare public-source case, with no ReflexFoundry helper or local inference. |
| Deterministic heuristic | Symbol lookup when an explicit symbol is provided, otherwise search. |
| Ordinary Laya | Untuned pinned Laya's raw choice, on this controlled public copy. |
| Trained always | The trained raw proposal, regardless of selective abstention, for this controlled read-only retrieval experiment. |
| Selective shadow | The actual guarded CLI advisory; the supplied failed policy returns search as fallback. |

The always arms are counterfactual experimental comparators. They grant no
production deployment, skip no mandatory validation, and never control
permissions, credentials, destructive operations or security approvals. Normal
product gates and the withheld deployment result remain intact.

Two tasks, two repetitions and five arms require **at most 20 new native coding
calls**. Each is limited to 180 seconds plus 5 seconds shutdown grace. The maximum
agent-process time is 60 minutes; subsequent local verification has three
90-second check limits per attempt. Orders are
counterbalanced across tasks and repetitions. Each case can be attempted once;
there is no automatic loop, retry, resampling or usage-reset-credit request.
Infrastructure or protocol failures halt subsequent launches for review.
The old study's 3 of 4 process starts are a separate historical cap.

## Frozen implementation and cost boundary

The local runtime is the actual downloaded public 0.2.1 wheel. Trained and untuned
weights, configuration, tokenizer bytes, the complete decision contract, report,
runner/worker/telemetry/task source, prompts, initial source, runtime versions,
and call order are pinned before any native execution. A changed input aborts.
The trained CPU policy has a fresh evaluation on the unchanged retained outcome
dataset. That is compatibility revalidation, not a new independent benchmark.

Laya 0.4.16 rewrites a `TokenizersBackend` tokenizer configuration during first
Torch loading. Initial immutable evaluation caught and rejected this change.
The proposed trained artifact records an explicit compatibility conversion in
a separate version: tokenizer JSON and weights are unchanged, while the class
alias becomes `PreTrainedTokenizerFast` and two loader-only fields are removed.
The original manifest is retained, all before/after hashes are recorded, and the
converted artifact was independently re-evaluated before freezing. The original
trained export and published numerical artifacts remain unchanged.
`scripts/native_cpu_artifact.py` reproduces that conversion into a fresh output;
it does not grant eligibility or silently overwrite historical evidence.

The original-agent cases contain only pinned public source with the declared
mutation. They receive the repair contract and the same mandatory checks, with
no generated runtime, request, policy, skill or retrieval instruction. They must
produce no worker receipt and run no local decision inference. The remaining
four arms must invoke the frozen retrieval worker exactly once, before editing.
It checks the prepared mutant digest at entry. The observer records a
validated compact worker receipt from the actual command-result event, including
model/request/contract identity and whether inference actually ran. An early
binding, domain or runtime refusal cannot count as a learned decision. Mutable
context/advisory files alone cannot establish inference. These are observable
process receipts, not cryptographic attestation against a malicious agent.

Primary workflow time includes native process startup, prompt delivery, local
inference and retrieval, agent repair, mandatory agent validation, and subsequent
independent focused/full/grader checks. Preparation/readiness and postcondition
audits are reported separately, along with the all-in attempt time. CLI-process
cold startup is measured; host load and operating-system caches are uncontrolled.
The worker’s inline identity audit is part of the executed workflow and is also
reported separately; its step time is not pure model inference. No energy,
hardware-FLOP, subscription-allowance or monetary conversion is made.

## Native access and privacy

The protocol explicitly selects documented `workspace-write` mode for a fresh
public case. It does not inherit a possibly read-only sandbox selection. Native
permission checks and policy rules remain enabled; there are no bypass flags,
credential changes or model/effort overrides. Separately billed APIs are not
authorized. Existing
native configuration and authenticated access are reused. The configured
hosting route has not been independently audited.

In the four intervention arms the agent may read the public case, generated retrieval runtime and local
policy/report metadata listed in the prepared plan. Weights are used by the
local inference process. Those files can enter the configured Codex service as
agent context, which is the precise egress requiring scoped approval after the
prior rejection. No private project source or transcripts are supplied.

The observer processes documented JSON events in memory, retaining only numeric
usage, allowlisted command counts, a validated fixed-worker receipt, final visible
answer, public candidates/hashes, and independent check results. Raw event
streams, reasoning text, command arguments and stderr text are discarded.
Missing/malformed token usage is unavailable, not zero. Optional reasoning-token
counts are numeric only and absent when unsupported. Token counts are not
money, energy, or a measure of the user's remaining subscription allowance.

The [official non-interactive documentation](https://learn.chatgpt.com/docs/non-interactive-mode)
describes `--json`, `turn.completed.usage`, final-message output and
`--ephemeral`; the installed CLI is 0.165.0. No private session logs are read.
